Уровни изоляции определяют, насколько строго защищены от влияния друг на друга параллельные транзакции. 
Чем выше уровень, тем надежнее данные, но медленнее работа (больше блокировок)

3 главные аномалии, которые возникают при параллельном чтении и записи

Грязное чтение. Это когда транзакция читает данные, которые были изменены другой транзакцией, но эта другая транзация еще не завершилась (не сделала коммит). Если первая транзакция потом откатится, то вторая транзакция останется с грызными, несуществующие данными
Неповторяющееся чтение. Транзакция один раз читает строку, а затем читает ту же самую строку и получает другие данные. Это происходит потому, что между чтениями другая транзакция успешно изменила эту строку и сохранила изменения.
Фантомное чтение - это когда транзакция выполняет один и тот же запрос с фильтром дважды и получает разное количество строк. Это происходит потому, что другая транзакция добавила и удалила строки, которые попадают под условия запроса.

В стандарте SQL определено 4 уровня изоляции:

Read Uncommited - чтение любых даже не подтвержденных данных. При таком уровне изоляции возможны все 3 типа аномалий
Read Commited - возможно чтение только закомиченных данных. Возможны аномалии неповторяющееся и фантомное чтение
Repeatable Read - БД замораживает строки, которая прочитала другая транзакция. Другие транзакции не могут их изменить, пока эта транзакция не завершит свою работу. В PG данный уровень изоляции решает не только проблему с неповиторяющимся чтением, но и с фантомным чтением.
Serializable - самый строгий уровень. БД делает все чтобы транзакции выполнялись так, как будто они идут строго последовательно, а не параллельно

На самом деле в БД PostgreSQL реализованы только 3 отдельных уровня изоляции. Т.е. режим Read Uncommited ведет себя точно также как и Read Committed. Это связано с тем, что это единственный разумный способ сопоставить стандартные уровни изоляции с многоверсионной архитектурой управления параллелизмом в PostgreSQL.

Установить уровень изоляции можно на:

конекретную транзакцию
сессию
все БД
Установка уровня изоляции через sqlalhemy:
В SQLAlchemy 2.x это делается через execution_options на уровне соединения (connection), привязанного к сессии через Dependency в FastAPI:
def get_db_strict_isolation():
db = SessionLocal()
try:
# Устанавливаем уровень изоляции ПЕРЕД началом любых запросов в этой сессии
db.connection().execution_options(isolation_level="REPEATABLE READ")
# Или "SERIALIZABLE" для максимальных гарантий в банке
yield db
finally:
db.close()

app = FastAPI()

@app.post("/transfer")
def transfer_money(amount: float, db: Session = Depends(get_db_strict_isolation)):
# Эта транзакция будет выполнена в REPEATABLE READ
# ... логика перевода ...
db.commit()
return {"status": "success"}
2. Уровень Сессии / Движка (Engine Level)
В веб-приложениях сессии SQLAlchemy живут очень недолго (один HTTP-запрос). Поэтому понятие "уровень сессии" на практике почти всегда означает "уровень движка (Engine)", от которого создаются все сессии.
Если вы хотите, чтобы все транзакции в этом микросервисе по умолчанию использовали REPEATABLE READ, вы задаете это при создании engine:
engine = create_engine(
"postgresql+psycopg2://user:pass@localhost/bank_db",
isolation_level="REPEATABLE READ" # <-- Задаем здесь
)
SessionLocal = sessionmaker(bind=engine)
